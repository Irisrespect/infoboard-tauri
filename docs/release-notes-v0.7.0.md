## v0.7.0 — API 测活插件 + 共用的"伴随程序"启动设施

本次把 [API 中转站测活工具](https://github.com/Irisrespect/api-probe) 接进 InfoBoard：
工具区一个图标，点开就用。顺带把"拉起外部工具"的逻辑抽成了两个插件共用的设施。

### 新功能

- **API 测活插件**（`plugins/api-probe/`）
  - 工具区一个图标，拉起独立的「API 中转站测活工具」：站点与多 Key 管理、
    模型列表探测、批量测速与流畅度、一键接入 Claude Code 与 Codex
  - 它**不随应用打包**（有自己的仓库、自己在迭代），所以第一次点会展开面板让你指定
    一次 `api_probe.py` 的位置，之后记住；配好之后再点图标就是**直接开**
  - 图标用宿主注册表里的 Lucide `activity`（脉冲折线），与截图/设置/翻译/网盘下载
    一致，都是具名线性图标

### 改进

- **宿主新增"伴随程序"设施**（`src-tauri/src/core/companion.rs`）：找解释器、找入口
  脚本、记住用户指定的路径，这些逻辑给多个插件共用；网盘下载器也改用它
  - **刻意不做"通用启动命令"**：每个程序一组命令（`netdisk_app_launch` /
    `apiprobe_app_launch`），插件只能启动自己那一个，借不了道去启动别的
  - 手动指定路径时校验**入口文件名**（必须是 `api_probe.py`），
    免得这个能力被当成"启动任意程序"的口子
- 两个启动器插件补上各自的 README；根 README 的功能表与项目结构同步更新

### 修复

- **CHANGELOG 里重复的 `0.6.0` 段**：那是"外部插件系统"的内容（属于 v0.4.0），
  一直挂着 `[Unreleased]`，上一版发版时被误改名成了 0.6.0。现已改正为 `0.4.0`

### 说明：为什么这两个工具都是"启动器"而不是插件内实现

InfoBoard 的插件运行在 WebView 中，受应用 CSP 约束 —— `connect-src` 只列了天气/B站
等少数域名，插件**发不出对任意域名的请求**，也没有写文件能力；而且插件只在面板打开时
活着。而这两个工具的核心恰好就是"发网络请求 + 写配置文件 + 长时间运行"：

| 工具       | 为什么必须独立                                                               |
| ---------- | ---------------------------------------------------------------------------- |
| 网盘下载器 | 要写下载的文件；直链 5~10 分钟就过期，面板一关就没人换链                     |
| API 测活   | 要发请求探测中转站；要写 `~/.claude/settings.json` 与 Codex 的 `config.toml` |

所以它们保持独立进程，插件只负责把窗口拉起来。

### 安装

1. 运行 `InfoBoard_0.7.0_x64-setup.exe`
2. 把插件包拖进 **设置 → 插件管理**：
   - `netdisk-1.2.0.ibplugin`（网盘下载）
   - `api-probe-1.0.0.ibplugin`（API 测活）
3. 两个工具都需要本机有 **Python 3.9+**（自带 tkinter，Windows 官方安装包默认带）。
   网盘下载器随安装包分发；API 测活工具第一次用需要指定一次它的位置
