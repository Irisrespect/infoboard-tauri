# 网盘下载 —— 设计与调研结论

> 输入网盘分享链接 + 提取码 → 自动解析目录 → 多连接高速下载。
>
> **交付形态（2026-10 起）**：下载跑在**独立软件**里，插件只是个入口。
>
> ```
> InfoBoard 工具区点「☁️ 网盘下载」
>         │  （宿主按 id 直接动作，不展开中间面板 —— 与截图插件同一套做法）
>         ▼
> netdisk_app_launch  →  pythonw netdisk-app/main.py  →  独立窗口
> ```
>
> |              | 独立软件（唯一有界面的路径）                     | 宿主里的应用内下载能力                          |
> | ------------ | ------------------------------------------------ | ----------------------------------------------- |
> | 在哪         | `netdisk-app/`（Python + Tkinter，**独立进程**） | `src-tauri/src/plugins/netdisk/{http,download}` |
> | 界面         | 自己的窗口                                       | **目前没有 UI 入口**（已从插件里撤掉）          |
> | 直链过期自愈 | ✅ 进程自己换链，关掉 InfoBoard 也照样下         | ⚠️ 要靠插件轮询触发，面板一关就断               |
> | 依赖         | 需 Python 3.10+（自带 tkinter，无需 pip）        | 无额外依赖                                      |
>
> 为什么把主力挪到独立软件：插件跑在 WebView 里**只在面板打开时运行**，而网盘直链
> 只有 5~10 分钟有效期 —— 面板一关就没人换链，大文件必然下不完。独立进程没有这个问题，
> 也不受应用 CSP（插件既不能直接发请求、也不能写文件）限制。
>
> 撤掉面板里的应用内下载之后，插件的权限也收紧了：`tauriCommands` 从 13 个降到 2 个
> （只剩"查状态 / 启动"），它再也拿不到 HTTP 转发、Cookie 读写、写文件这些能力。
> 宿主那套 `netdisk_http_request` / `netdisk_download_*` 仍然保留、测试也还在跑
> （28 项），但**当前没有调用方** —— 留着是为了将来要做"不装 Python 也能下"时的复用。
>
> 独立软件目前**只实现了夸克**。下文是两条路径共用的协议与设计依据。

## 0. 先说结论：哪些能"免费高速"，哪些不能

**"免费 + 高速"在技术上只对一部分网盘成立，而且原因不在客户端。**

限速分三种，必须区分清楚：

| 类型                                        | 表现                             | 多连接分片能不能救            |
| ------------------------------------------- | -------------------------------- | ----------------------------- |
| **单连接限速**（服务端按连接限速）          | 一个连接慢，多开几个就快         | ✅ 能，这正是本插件在做的事   |
| **按连接限速 + 账号总量天花板**（夸克）     | 多开连接近似相加，但总量有上限   | ✅ 能，开到一定程度后收益归零 |
| **账号级限速**（服务端按账号/文件聚合限速） | 开 4/8/16 个连接，**总速度不变** | ❌ 不能，客户端无解           |

实测与社区结论（2026-10 调研，来源见文末）：

| 网盘                       | 免费下载速度                    | 多线程能否加速                    | 结论                       |
| -------------------------- | ------------------------------- | --------------------------------- | -------------------------- |
| **夸克网盘**               | 单连接 40–80 KB/s，多连接可叠加 | ✅ **能**（16–32 连接到 MB/s 级） | **按连接限速，值得开并发** |
| **蓝奏云**                 | 官方不限速                      | ✅ 能跑满带宽                     | **真正的免费高速**         |
| **任意直链**（支持 Range） | 取决于服务端                    | ✅ 能                             | 通用兜底                   |
| 阿里云盘                   | 1–3 MB/s                        | ⚠️ 部分（受 API 配额/并发限制）   | 可用                       |
| **百度网盘**               | 20–80 KB/s                      | ❌ 账号级聚合限速                 | **只有 SVIP 能提速**       |

> ⚠️ **勘误**：本文早期版本把夸克也归进"账号级限速、多线程无效"，**这是错的**。
> 那个结论是从 OpenList 文档"夸克下载慢是因为需要会员"一句推测出来的，而 OpenList
> 的夸克驱动**只做本机单路串流代理**（`WebProxy=true`，Link 里写死 `Concurrency: 3`），
> 慢是它自己的架构问题，不能拿来证明"多线程无效"。夸克真实机制是**按连接给配额**。

### 夸克：为什么多连接有效，以及天花板在哪

实测与源码注释（GeZi 下载器，2026-10）给出的机制是三层叠加：

1. **按连接配额**：单连接被压到常态 **40–80 KB/s**，N 路近似相加 —— 所以多线程有效。
2. **节点 IP 配额**：限速可能绑定在边缘节点 IP 上，同一节点开太多路会被统一压制。
3. **账号级总连接数上限**：存在聚合天花板。实测 **512 连接 22.33 MB/s vs 1024 连接
   23.20 MB/s**（+5%，但单连接速度腰斩），说明超过某个总量后加连接不再有收益。
   另有"片少（并发×1.5）3–5 MB/s vs 片多（并发×32）20–100+ MB/s"的对照实测。

时间维度同样关键：存在**整体塌陷时段**（实测出现过 335/339 路低于 12 KB/s、平均
840 B/s），所以"同一套设置今天快明天慢"属于正常现象。

还有两个必须遵守的约束：

- **UA 要前后一致**：夸克 CDN 会校验"取直链时声明的身份"与"实际下载时的身份"。
  取链用客户端 UA（`quark-cloud-drive/3.14.2 … Channel/pckk_other_ch`）、下载却换成
  浏览器 UA，等于自证不是客户端，会被判盗链而降速甚至 412。本插件两步用同一个 UA。
- **直链 5–10 分钟就过期**：过期表现为 401/403/412。9GB 文件按 9MB/s 跑 17 分钟会撞上
  2~4 次。本插件遇到这几个状态码会**立即失败并明确提示"重新解析"**（而不是傻等重试）。

**本站的取舍**：默认 16 连接、可选到 64（社区建议单文件 ≤64 路）；分片数取连接数的
**8 倍**并采用**抢占式取片**（快的连接下完一片就抢下一片），正对应上面"片多比片少快得多"
的实测 —— 静态等分会让整体速度卡在最慢的那条连接上，表现为"尾部掉速"。

所以，下面这些"经典操作"在当前（2026）**已经失效或不该做**，本插件刻意没有实现：

- ❌ **伪 SVIP User-Agent**（`netdisk;P2SP;…`、`LogStatistic`）：AList/OpenList 官方文档已把
  Crack 接口标注"非官方接口已无法使用"。现在 `pan.baidu.com` 这个 UA 只是**通过防盗链的
  必要条件**（>20MB 文件不带就 403），**不是加速手段**。
- ❌ **多账号 / 多线程硬堆百度**：账号级聚合限速，实测 4/8/16 并发总量不变。
- ❌ **第三方"在线解析"服务**：时效差、随时收费下线，而且要经手用户的 Cookie。
- ⚠️ **PanDownload / KinhDown 一类工具**：前者作者已被抓、项目关停；后者 2026-04
  服务器被执法部门接管。这条路有明确法律风险，不要碰。

**本插件的定位**：把"能靠并发提速的"（夸克、蓝奏云、未限速直链）真的开到高速，
把"确实做不到的"（百度免费号）如实告诉你，而不是假装能加速。

## 1. 为什么必须改宿主（纯插件做不到）

外部插件的运行时约束（见 [PLUGIN_PACKAGE.md](PLUGIN_PACKAGE.md)）：

1. **单文件入口**，只能 import 白名单 4 个模块：`react`、`react/jsx-runtime`、
   `react-dom`、`@tauri-apps/api/core`；相对路径和 npm 包一律报错。
2. **`invoke` 受 `tauriCommands` 约束**（fail-closed），且只能调宿主已注册的命令。
3. **没有网络能力**：应用 CSP 的 `connect-src` 只列了天气 / B 站等少数域名，
   插件 `fetch` 网盘接口会被 CSP 拦掉；即使放行也会撞 CORS。
4. **没有文件写入/下载能力**：`@tauri-apps/plugin-*` 全部不在白名单。
5. **不能用 `@tauri-apps/api/event`**：插件无法 `listen`，所以下载进度只能**轮询**。

结论：**"发请求"和"写文件"这两件事必须由宿主 Rust 提供。** 于是新增了
`src-tauri/src/plugins/netdisk/`，插件只负责各家网盘的协议逻辑（解析、列目录、取直链）。

```
┌──────────────── 插件 (index.tsx，单文件) ────────────────┐
│  UI：链接/提取码输入 · 文件列表 · 下载队列 · 设置          │
│  适配器：夸克 · 蓝奏云 · 百度 · 直链（可扩展）              │
└───────────┬───────────────────────────┬─────────────────┘
            │ invoke                     │ invoke
            ▼                            ▼
┌── netdisk_http_request ──┐   ┌── netdisk_download_start ──┐
│ 域名白名单 + Cookie 罐    │   │ Range 探测 → N 个分片任务   │
│ 可带任意头 / POST / 重定向 │   │ 随机写同一文件（seek_write）│
│ 每一跳重定向都重新校验     │   │ 进度由 list/status 轮询     │
└──────────────────────────┘   └────────────────────────────┘
```

### 新增的 Rust 命令

| 命令                                            | 作用                                                       |
| ----------------------------------------------- | ---------------------------------------------------------- |
| `netdisk_http_request`                          | 带 Cookie 罐的 HTTP 转发（GET/POST/PUT/PATCH/DELETE/HEAD） |
| `netdisk_cookie_import` / `_list` / `_clear`    | 手工粘贴 / 查看 / 清除登录 Cookie                          |
| `netdisk_download_start`                        | 启动下载：探测 → 建文件 → 切分片 → 并发拉取                |
| `netdisk_download_status` / `_list` / `_cancel` | 单个 / 全部任务状态、取消                                  |
| `netdisk_default_download_dir`                  | 默认下载目录（系统"下载"文件夹）                           |
| `netdisk_reveal_in_explorer`                    | 在资源管理器里定位文件                                     |

安全约束（这部分是刻意收紧的）：

- 域名白名单 `src-tauri/src/plugins/netdisk/domain.rs`，只放行网盘相关域名；
  否则这个命令就成了插件的"匿名代理"。
- **重定向的每一跳都重新校验白名单**（防止白名单站点把请求 302 到内网）。
- Cookie 罐**按可注册域分桶**：`pan.baidu.com` 的 Cookie 不会发到 `pan.quark.cn`。
- 默认只允许 https，少数站点（蓝奏云）由适配器显式传 `allowHttp` 才放行。

## 2. 高速下载是怎么实现的

`src-tauri/src/plugins/netdisk/download.rs`：

1. **探测**：`GET` + `Range: bytes=0-0`
   - 回 `206` + `Content-Range: bytes 0-0/总长` → 支持分片，拿到总长
   - 回 `200` → 服务端忽略 Range → **自动退回单连接**（绝不硬分片）
2. **切分片（动态队列，不是"一人一段"）**：片数 ≈ 连接数 × 32，单片 ≥ 256KB，片数上限 16384。
   每个连接下完一片就回来抢下一片 —— 静态等分会让整体速度卡在**最慢的那条连接**上，
   表现为"尾部掉速/停滞"。这正是实测里"片多（并发×32）20–100+ MB/s vs
   片少（并发×1.5）3–5 MB/s"以及"256KB/片 23.65 > 512KB/片 12.94 > 1MB/片 6.58"的差别来源。
3. **并发写同一文件**：Windows 用 `File::seek_write`（overlapped，不移动文件游标），
   Unix 用 `write_at`，因此**不需要"下成一堆分片再合并"**，省掉一次全量 IO。
4. **直链自愈（长任务的命门）**：直链只有 5~10 分钟有效期，大文件必然中途过期。
   - 某个分片撞上 401/403/404/412 → 把该分片**放回队首**、任务状态置 `expired`，挂起等换链
   - 插件轮询到 `expired` 就重新解析分享、调 `netdisk_download_relink` 送新直链
   - 后端收到新链后**从未完成的分片继续**，已下完的分片不重下（实测计数不会重复累加）
   - 最多自动换链 5 次；3 分钟等不到新链才判失败
5. **限流退避（429/503）**：不是只退避当前分片，而是让**所有** worker 一起静默
   （首次 30 秒、随后翻倍、上限 5 分钟）—— 限流是服务端对这个账号/链路的，
   其它连接继续猛冲只会加重惩罚。
6. **慢分片抢占**：某个分片 15 秒没收到一个字节 → 交回队列让别的连接试
   （已写下的字节仍然有效，重新排队后从断点续传）；同一个分片最多重排 3 次。
7. **分片内重试**：单个分片内部按已完成的偏移续传，最多重试 4 次。
8. **进度**：原子计数 + 轮询时用增量估算速度（插件无法 `listen` 事件）。

连接数上限 64、默认 16（社区建议单文件 ≤64 路；再加会撞账号级总量天花板并徒增风控风险）。
百度由适配器锁死在 1 路（见下）。

测试覆盖（`cargo test --lib plugins::netdisk`，28 项）：

- 起一个**本地 HTTP 服务**真的跑一遍 8MB+零头的分片下载，**逐字节比对**内容
  （偏移写错必然失败）—— 这是最容易写错、也最该被测的一段
- **片数远多于连接数**时内容仍逐字节一致、且计数不超总长（重复下同一片会立刻暴露）
- **直链过期 → 挂起 → 换链 → 从断点下完**：服务端发够 2MB 后就一律 403 模拟过期，
  断言任务进入 `expired`（而不是 `failed`）、换链后逐字节一致、且计数正好等于文件大小
  （证明已完成的分片没有被重下）
- 探测阶段就 403 时立刻报错（挂在那里等换链才是错的）
- 服务端不支持 Range 时正确退回单连接；取消；连不上时快速报错
- 分片计划的边界（1 字节、连接数为 0、400GB 超大文件不超片数上限）
- 文件名清洗、重名另存、Cookie 域隔离与超长 Cookie 预警、白名单伪造后缀、直链过期提示文案

## 3. 各网盘的接入细节（调研记录，2026-10）

### 夸克网盘 ✅ 免登录可列目录

```
1) POST https://drive-pc.quark.cn/1/clouddrive/share/sharepage/token?pr=ucpro&fr=pc&uc_param_str=
   body {"pwd_id":"<分享ID>","passcode":"<提取码>"}     → data.stoken     （免登录，实测 200）
   注意：提取码错误时这一步不报错，错误会在第 2 步暴露
2) GET  /1/clouddrive/share/sharepage/detail?pwd_id=&stoken=&pdir_fid=0&_size=200&_sort=...
   → data.list[]（fid / file_name / size / dir / share_fid_token）    （免登录，实测 200）
3) POST /1/clouddrive/file/download    ★免转存
   body {"fids":[fid], "fids_token":[share_fid_token], "pwd_id":…, "stoken":…}
   → data[0].download_url
4) 直链 GET（必须带会话 Cookie）  Range: bytes=start-end  → 206 + 分片字节
```

**第 3 步是"免转存"**：直接把分享的 `fid` + `share_fid_token` 换成直链，
**不往用户网盘写任何东西** —— 不占空间（网盘满了也能下）、不需要事后清理、
少两次远端状态变更（save + delete），风控面更小。
插件默认走这条路，走不通才回落到「转存 → 取直链」的兜底路线。

- 必需 Cookie：`__uid`、`__puus`（`__pus` 由响应回写；`_UP_*` 系列可作登录态旁证）
- **直链必须带会话 Cookie**：不带一律 `412 Precondition Failed`（实测对照）。
  连匿名会话的 `__sdid` 也算 —— 取链和下载要用同一个会话
- 请求头要 `User-Agent: …quark-cloud-drive/3.14.2…Channel/pckk_other_ch` + `Referer/Origin: https://pan.quark.cn`
- **取直链与下载必须用同一个客户端 UA**（夸克会做身份一致性校验，混用会降速或 412）
- 直链 host 形如 `dl-pc-zb.drive.quark.cn`（登录）/ `dl-guest-sz-u.drive.quark.cn`（匿名），
  **支持 Range/206**，已在宿主白名单内（`quark.cn` 覆盖其子域）。
  **从域名前缀就能看出当前是哪个档位**
- 直链 **5–10 分钟过期**，过期表现 401/403/412；大文件要预期中途需要重新解析

#### 匿名档 vs 登录档（本机实测，2026-10-18）

| 维度       | 匿名（不登录）                                               | 登录后                                                            |
| ---------- | ------------------------------------------------------------ | ----------------------------------------------------------------- |
| 单文件大小 | **≤ ~50MB**（38.6MB 成功 / 68.6MB 被 `code 23018` 拒）       | 1.2GB+ 正常（实测 1278MB `code=0`）                               |
| 速度       | 0.17–0.75 MB/s，**加并发无效**（32/64/128/256 都是这个量级） | 64 路 3.04 / 128 路 6.13 / 256 路 11.77 / **512 路 21–23.7 MB/s** |
| 单连接     | 0.31 MB/s                                                    | 0.12 MB/s（≈每连接限 120KB/s）                                    |
| 分片粒度   | —                                                            | 512 路下：**256KB → 23.65**、512KB → 12.94、1MB → 6.58 MB/s       |

→ 两个直接结论：

1. **匿名通道是按"整体"限速的**，开多少连接都没用 —— 小文件走匿名只为"零账号风险"，
   不要为它调高并发；
2. **登录档是按"连接"限速的**，并发近似线性叠加，且**片越小越快**。
   本插件因此把最小分片定为 **256KB**、片数做到连接数的 32 倍。

#### 其它必须遵守的约束

- **Cookie 必须按域过滤**：把浏览器全部 Cookie（约 7.2KB）一起发 → 服务端直接掐连接
  （IncompleteRead / ChunkedEncodingError）；只发该网盘域的 25 项就正常。
  宿主已按可注册域分桶，并对超限的 Cookie 头给出可照做的报错。
- **连接数是账号级总量**：夸克按账号限制总连接数（社区实测 512 为最优总量，
  512→1024 总速几乎不变）。所以**一次排多个文件时不能每个都开满** ——
  插件按文件大小把 512 的连接预算分给这一批任务（大文件多给、小文件保底 4 路）。
- `file/download` 的 `fids` 官方限制 **≤50 个/次**（本插件逐文件取链，不受影响）。
- 查询串变体：`pr=ucpro&fr=pc&uc_param_str=` 可用；**`fr=android` 会 401，不要用**。
- `stoken` 实测 ≥10 分钟有效；遇到 `14001` 应重新取链。
- **错误码 23018** = 未登录时的大小限制（不是"大文件一律不能下"，登录即解除）。
- 工程细节：每个分片新建连接会撞 `WinError 10054`（TIME_WAIT 耗尽本机端口），
  必须用长连接池 —— reqwest 的 `Client` 自带连接池，本实现共享同一个 `Client`。

### 蓝奏云 ✅ 免登录、不限速（但需要跟着站点改）

```
1) GET 分享页 → 若响应里有 var arg1='…' 说明撞了 acw_sc__v2 WAF
   → 用固定表重排 + 与固定 key 异或算出 acw_sc__v2，写 Cookie 后重放
2) 有提取码 → POST 同一地址 body pwd=xxxx
3) 页内 <iframe src="/fn?…"> → GET 它 → 拿到 ajaxm.php 地址 + sign + p
4) POST {ajaxm} body action=downprocess&sign=…&p=…&kd=1 → {"zt":1,"dom":…,"url":…}
5) 直链 = {dom}/file/{url}，带 Referer 下载
```

站点结构多变，失败时插件会给出明确提示（可改用「直链下载」手动兜底）。

### 百度网盘 ⚠️ 能解析，但基本没法免费高速

```
1) POST /share/verify?surl=<去掉前导 1 的 ID>&t=<ms>   body pwd=…  → 下发 BDCLND
2) GET  /s/1<surl>?pwd=…   → 正则抓页面内嵌 locals.mset({…})
   → 一次拿到 shareid / share_uk / file_list[]
3) POST /share/transfer   转存到自己网盘的中转目录
4) 下载走 d.pcs.baidu.com/rest/2.0/pcs/file?method=download&app_id=250528&path=…
   必须带 User-Agent: pan.baidu.com（否则大文件 403）
```

- 需要登录：`BDUSS` + `STOKEN`（STOKEN 要取 `.pan.baidu.com` 域的）
- **web 端 dlink 已大面积 `31362 sign error`**，所以走 PCS 接口
- 第 4 步就是限速环节：非会员 20–80KB/s，**多连接无效**
- ⚠️ **百度的并发必须锁 1 路**：它不是"多开没用"，而是"多开会主动招来惩罚"。
  BaiduPCS-Go 作者原话是普通用户应把 `max_parallel` / `max_download_load` 都设为 1，
  "调大线程数只会在短时间内提升下载速度，且极易很快触发限速，导致**几小时至几天内
  账号在各客户端都接近 0 速**"；SVIP 也建议 10–20 且不超过 20。
  所以插件在适配器层直接钉死为 1。
- 插件当前只支持"分享根目录"下的文件；子目录分页接口不稳定，已明确报错而不是假装支持

### 按网盘区分的并发策略（不能用同一个"线程数"滑块通吃）

| 网盘     | 限速维度   | 并发上限 | 说明                                                            |
| -------- | ---------- | -------- | --------------------------------------------------------------- |
| 夸克     | 按**连接** | 64       | 并发近似线性叠加；但账号级总连接数有天花板（社区实测 512 最优） |
| 蓝奏云   | 不限速     | 32       | 能跑满带宽，开太多只是徒增请求                                  |
| 百度     | 按**账号** | **1**    | 并发会触发惩罚性限速，可能持续数小时到数天                      |
| 任意直链 | 看服务端   | 用户设置 | 支持 Range 才有意义                                             |

另外，**一次排多个文件时不能每个都开满**：夸克按账号限总连接数，所以插件把 512 的
连接预算按文件大小分给这一批任务（大文件多给、小文件保底 4 路）。

## 4. 使用

1. 重新构建应用（**必须**，否则没有新的 Rust 命令）：
   ```bash
   npm run tauri build      # 产出 NSIS 安装包
   # 或开发态：npm run tauri dev
   ```
2. 安装插件，二选一：
   - 把 `dist-plugins/netdisk-1.0.0.ibplugin` 拖进 **设置 → 插件管理**
   - 或把 `plugins/netdisk/` 拷到 `%APPDATA%\com.infoboard.tauri\plugins\netdisk\`，
     再点 **设置 → 插件管理 → 重新加载插件**
3. 工具区点 **☁️ 网盘下载** → 粘贴链接（如 `https://pan.quark.cn/s/xxxx`）+ 提取码 → 解析
4. 需要登录的网盘：浏览器打开该网盘 → F12 → 复制 Cookie → 插件「设置 → 设置登录」粘贴

## 5. 排错

| 现象                          | 原因 / 解决                                                                                        |
| ----------------------------- | -------------------------------------------------------------------------------------------------- |
| `插件未声明命令 "xxx"`        | `manifest.json` 的 `tauriCommands` 漏了；`src/__tests__/netdiskPlugin.test.ts` 会在 CI 提前拦下    |
| `域名不在网盘白名单内: xxx`   | 该网盘的 CDN 域名没进 `domain.rs` 的 `ALLOWED_HOSTS`，按提示加上即可                               |
| `服务端忽略了 Range 请求`     | 该直链不支持分片，属正常回退；下载仍可完成，只是不快                                               |
| `下载停滞`                    | 分片被反复重排或直链被限速；重新解析一次，或调低并发连接数                                         |
| 队列显示「直链过期，换链中…」 | 正常自愈过程：后端在等新直链，插件会自动重新解析并续传。一直停在这里说明换链失败（会同时弹出原因） |
| 触发限流（429/503）           | 后端会全局退避（首次 30 秒、随后翻倍、上限 5 分钟）后自动继续                                      |
| 夸克 `401`                    | 登录态失效，重新粘贴 `__uid`/`__puus`                                                              |
| 夸克 `23018`                  | 匿名档只能下约 50MB 以下的文件，登录后解除                                                         |
| 夸克转存失败                  | 走免转存路线时不该出现；若出现说明落回了兜底路线，多半是网盘空间不足或转存过频                     |
| 百度 `-62`                    | 风控要求验证码，先在浏览器里打开一次该分享链接                                                     |
| 蓝奏云解析不到入口            | 页面结构变了，或这是文件夹分享；用「直链下载」手动兜底                                             |

## 6. 想再支持一个网盘？

只需在 `plugins/netdisk/index.tsx` 里加一个 `Adapter` 对象（约 40 行）：

```ts
const myAdapter: Adapter = {
  id: 'xxx', name: '某网盘', icon: '🟢', session: 'xxx',
  cookieHost: 'pan.xxx.com', rootId: '0',
  speedNote: '免费速度说明（如实写）',
  loginHint: '需要哪些 Cookie',
  match: (url) => /(^|\.)xxx\.com$/i.test(hostOf(url)),
  parse: async (url, pwd) => ({ ctx: {…}, entries: [/* FileEntry */] }),
  list:  (ctx, dirId) => Promise<FileEntry[]>,
  resolve: (ctx, file) => Promise<{ url, headers?, fileName? }>,
}
```

然后把它加进 `ADAPTERS`（顺序即优先级，`direct` 必须留在最后当兜底），
并在新网盘的域名加进 `domain.rs` 的 `ALLOWED_HOSTS` + 跑一遍
`cargo test --lib plugins::netdisk` 与 `npx vitest run`。

## 7. 合规与风险

- 插件只使用**用户自己的账号 Cookie**，不内置任何第三方账号，也不内置
  任何"在线解析"服务（避免把用户凭据交给第三方）。
- 自动化请求频率应保持克制：夸克转存、百度转存过频都会触发风控。
  社区建议**单文件 ≤64 路并发**，遇 429/403 或速度骤降应立即降档。
- 网盘服务条款通常禁止绕过限速。需要区分两种情况：
  - **多连接下载**：用的就是服务端自己给的 `Range` 能力，属于正常下载方式，
    本插件做的是这个；
  - **伪造身份 / 破解接口**（伪装 SVIP UA、"Crack" 接口）：本插件**没有**做。
    夸克那个客户端 UA 的作用是**通过它的合法校验**（不带会被拒），
    不是"破解"，而且官方要求前后一致。
- 下载内容请自行确保有合法权利。

## 8. 已知限制 / 下一步

- **直链过期**：已实现**自动换链 + 断点续传**（撞上 401/403/412 → 状态 `expired` →
  插件重新解析 → `netdisk_download_relink` → 从未完成的分片继续，最多 5 次，
  3 分钟等不到新链才失败）。剩余不足：
  - **换链由插件轮询触发，而插件只在面板打开时运行** —— 所以**长任务请保持面板打开**，
    关掉面板后直链过期就没人来重新解析了（下载队列里已给出提示）。要彻底解决，
    得让宿主自己理解各家网盘协议，或让插件常驻（当前插件模型不支持）。
  - 换链期间任务会短暂停顿（通常 1~2 秒）；`stoken` 也过期时需要重新解析整个分享。
- **百度**只支持分享根目录、且非会员基本没法用（账号级限速）。
- **扫码登录**尚未实现：目前靠用户从浏览器复制 Cookie。更省事的做法是用独立
  Edge + CDP（`--remote-debugging-port` + `--user-data-dir`）扫码，一次登录长期有效；
  但 CDP 需要 WebSocket 客户端（Rust 侧要加依赖），且二维码识别/轮询状态机
  细节不少，所以留到后面做。
- **阿里云盘 / UC / 123 / 天翼 / 移动** 尚未接入，原因见第 3 节末表。
